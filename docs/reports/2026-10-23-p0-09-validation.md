## Regression coverage

Nine new regression groups test wallet payment/topup numeric coercion/precision/currency, negative and oversized nested settlement totals, exact 0.1/0.2/0.29 arithmetic and balance ceilings, mobility duration/resource validation, required utility/fine/food/housing IDs, nested preferences/prototype keys, malformed direct inputs, core validation before session/action consumption, and actual HTTP rejection across all six service servers.

Rejected requests are compared against a snapshot of balances, ledger/fines, parking/rides, toll state, bill/orders, preferences and core sessions, proving no observable fixture state mutation. Existing schema tests now require successful invocation using actual created resource IDs and sufficient funds, rather than accepting fallback resources or arbitrary error envelopes.

Input schemas are shared by request handlers, catalog and legacy tool descriptors. Requests are not coerced, defaulted or silently stripped. Capability versions are 2.0.0 for tightened required parameters; the catalog envelope remains 1.0.0. Monetary arithmetic uses integer minor units; total/balance caps are 1,000,000 demo units and duration caps are 720 demo hours. Decimal input must be finite, positive and at most two fractional digits.

## Remaining boundaries

This closes input-validation scope, not production finance or authorization. The fixture wallet still mixes USD legacy and AED civic examples and retains simulated card fallback behavior; P0-06/P1-13 must replace those semantics. Core false-success/error handling is P0-12, durable idempotency/concurrency is P0-06/P0-10 and immutable resource-bound approvals remain P0-04. Known UI empty-choice behavior remains P1-12. Read-side fabricated tracking remains P1-13.

Real Keycloak, Docker, browser and Flutter were not executed for this change. The JS build type-checks Node/protocol/mini-app source and bundles React/Angular; it is not a native/container deployment test.
