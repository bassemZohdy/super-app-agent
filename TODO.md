# Super App Agent — backlog

> **This file is the only place where task status is tracked.** Delivered work lives in the [changelog](docs/CHANGELOG.md), verification results in the [evidence register](docs/reports/README.md), and what exists today in the [README](README.md#what-exists-today). Delivery target: the local synthetic demo ([ADR-0011](docs/adr/ADR-0011-local-demo-target.md)). No real money, agency credentials or hosted deployment is implied, and the production gate at the bottom does not block the demo.

## How to work this file

Agent rules are in [AGENTS.md](AGENTS.md).

- One bullet per task: scope that is **still open**, then `Done when`. A bullet stays under 700 characters (`npm run check:docs` enforces it). Design and history belong in the guide or the changelog, not here.
- Show partial work with indented sub-steps (`[x]` landed, `[ ]` open), never with prose. Delete a task here and add its changelog entry in the **same commit** that meets `Done when`.
- Work the [critical path](#critical-path) in order. Take something off it only when the critical path is blocked, and say why in the commit message.
- Documentation per slice: one changelog entry, plus the guide you changed. An evidence report is written per milestone, not per slice. Outside dated evidence reports, do not record test totals, task counts or percentages; they go stale.
- Run the narrowest test while iterating (`node --experimental-strip-types --import ./scripts/test-env.ts --test services/test/<file>.ts`) and the full `npm run check` before pushing a checkpoint.
- Do not re-enable disabled GitHub workflows. Dependency advisories, native/device validation, external security approval and production HA are production-gate work.

## Completion policy

A generated surface, mock receipt, declared test, compiled schema, gateway YAML or green type-check is not proof of a real integration, business success or production authorization.
